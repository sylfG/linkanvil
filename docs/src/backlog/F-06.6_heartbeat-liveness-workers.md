**Descripción:**
Como Operador
Quiero **que los workers (sin endpoint HTTP) reporten un heartbeat a Redis y que Docker los considere unhealthy si dejan de hacerlo**
Para distinguir un worker "vivo pero colgado" (deadlock, socket bloqueado) de uno realmente activo, sin esperar a un crash que reinicie el contenedor.

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** los tres workers están consumiendo mensajes,
  **Cuando** Docker ejecuta el healthcheck cada 30s,
  **Entonces** el script lee `worker:<name>:heartbeat` de Redis (TTL 45s, refrescado cada 15s) y reporta healthy.

- [ ] **Edge Case:**
  **Dado que** un worker se cuelga en una llamada externa pero no crashea,
  **Cuando** transcurre la ventana TTL,
  **Entonces** la clave expira, el healthcheck falla y Docker marca el contenedor como unhealthy (visible en `docker ps`).

- [ ] **Requisito Técnico:**
  `src/data/heartbeat.py` expone `start_heartbeat(redis, name)` que crea un `asyncio.Task` cancelable (interval 15s, TTL 45s; configurable por env). Cada worker lo arranca en `connect()` y lo cancela en `close()`. Healthcheck del compose: `python -c "import redis,os,sys; r=redis.Redis.from_url(os.environ['REDIS_URL']); sys.exit(0 if r.get('worker:<name>:heartbeat') else 1)"`. `reset.sh` espera a estos contenedores junto con los demás.
