**Descripción:**
Como Actor
Quiero **LLM Gateway con Circuit Breaker, Fallback Automático entre proveedores y caché local**
Para que la funcionalidad orientada a eventos opere.

**Criterios de Aceptación (Checklist):**

- [x] **Happy Path (routing least-busy):**
  **Dado que** un cliente interno (scraper, embedder, chat) llama `POST /v1/chat/completions` o `/v1/embeddings` contra LiteLLM con `model: "cerebro-lite"` / `"cerebro-pro"` / `"cerebro-embeddings"`,
  **Cuando** LiteLLM Router aplica `routing_strategy: least-busy`,
  **Entonces** despacha la llamada al backend NVIDIA NIM menos ocupado del grupo y devuelve la respuesta upstream (verificado en `infra/litellm/config.yaml:69-76`).

- [x] **Edge Case (fallback automático entre backends del mismo grupo):**
  **Dado que** un backend del grupo falla con error 5xx o timeout `>90s`,
  **Cuando** `allowed_fails: 1` se alcanza,
  **Entonces** LiteLLM marca el backend en cooldown `cooldown_time: 15` (s), reintenta hasta `num_retries: 3` veces y rutea al siguiente backend del grupo (p.ej. `meta/llama-3.1-8b-instruct` → `mistralai/mixtral-8x7b-instruct-v0.1` dentro de `cerebro-lite`, o `meta/llama-3.3-70b-instruct` → `nvidia/llama-3.3-nemotron-super-49b-v1.5` en `cerebro-pro`) (verificado en `infra/litellm/config.yaml:44-49, 69-76`).

- [x] **Edge Case (caché Redis para respuestas idempotentes):**
  **Dado que** una petición de completion o embedding repite prompt+modelo+params,
  **Cuando** LiteLLM consulta cache Redis,
  **Entonces** sirve la respuesta cacheada sin llamar al backend (TTL 3600s, namespace Redis compartido con el resto de servicios vía `host: redis`) (verificado en `infra/litellm/config.yaml:50-57`).

- [x] **Edge Case (presupuesto y paralelismo global):**
  **Dado que** se acumulan llamadas concurrentes,
  **Cuando** se alcanza `global_max_parallel_requests: 100` o `max_budget: 50`,
  **Entonces** LiteLLM rechaza nuevas peticiones con 429/403 según política (verificado en `infra/litellm/config.yaml:66-67`).

- [x] **Requisito Técnico:**
  - 3 grupos de modelos:
    - `cerebro-lite` — 2 backends (llama-3.1-8b-instruct, mixtral-8x7b-instruct-v0.1).
    - `cerebro-pro` — 2 backends (llama-3.3-70b-instruct, llama-3.3-nemotron-super-49b-v1.5).
    - `cerebro-embeddings` — 1 backend (nv-embedqa-e5-v5, `encoding_format: float`).
  - Provider único: **NVIDIA NIM** (`api_base: https://integrate.api.nvidia.com/v1`) con `NVIDIA_API_KEY` desde env.
  - Política de retries: `num_retries: 3`, `retry_after: 3s`, `request_timeout: 90s`, `allowed_fails: 1`, `cooldown_time: 15s`.
  - Cache Redis: `type: redis`, `ttl: 3600s`, `supported_call_types: ["completion", "embedding"]`.
  - Auth interna: `master_key` desde env `LITELLM_MASTER_KEY` (file-based en prod vía `LITELLM_KEY_FILE`).
  - Persistencia: `database_url` apunta a Postgres para `store_model_in_db: true` (virtual keys BYOK — slice del backlog F-08).

**Decisiones tomadas tras el backlog original** (drift documentado):
- **Provider único NVIDIA NIM**: no se usa multi-provider real (OpenAI/Anthropic/etc.). El "fallback entre proveedores" del título se materializa como fallback **entre modelos del mismo provider**.
- **Nemotron 70b retirado**: la cuenta NIM dejó de servir `nvidia/llama-3.1-nemotron-70b-instruct` (404 "Function not found"); sustituido por `nemotron-super-49b-v1.5` + `llama-3.3-70b-instruct` como fallback.
- **"Circuit Breaker"**: implementado vía `allowed_fails`+`cooldown_time` de LiteLLM (no es un Hystrix-like dedicado).
- Comentarios en `config.yaml` documentan estas decisiones in-code.
