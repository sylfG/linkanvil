**Criterios de Aceptación (Checklist):**

- [x] **Happy Path Redis — Redis Stack con RedisBloom + AOF + LRU:**
  **Dado que** el servicio `redis` usa la imagen `redis/redis-stack-server:latest@sha256:798ab84d…` (pinneada por digest, ver F-00.11),
  **Cuando** `docker compose up redis`,
  **Entonces** arranca con:
  - **Módulo RedisBloom incluido** (Redis Stack lo trae por defecto): comando `BF.RESERVE` usado en `src/ingestion/deduplicator.py:36` para el bloom filter de deduplicación per-tenant (F-01.1).
  - **REDIS_ARGS**: `--requirepass <pwd> --maxmemory 512mb --maxmemory-policy allkeys-lru --save 60 1000 --appendonly yes`
    - `allkeys-lru` evita OOM en el límite de 768M.
    - `--appendonly yes` activa AOF para durabilidad de sesiones/CSRF.
    - `--save 60 1000` snapshot RDB de respaldo cada 60s si hay ≥1000 writes.
  - Volumen persistente `redis-data:/data`.
  - Healthcheck `redis-cli -a <pwd> ping`.
  (verificado en `docker-compose.yml:389-412`).

  **Usos principales en el código**:
  - Bloom filter dedup: `bf:tenant:{tenant_id}:ingestion` (`src/ingestion/deduplicator.py`).
  - Rate-limit por tenant: `INCR + EXPIRE` atómico (`src/ingestion/main.py:120-130`, `src/api/main.py:645-652`).
  - Session cookies + CSRF: `cerebro_session`, `cerebro_refresh`, `cerebro_csrf` (`src/api/main.py:534-555`).
  - Cache LiteLLM responses (TTL 3600s, ver F-02.2).
  - Mapping Telegram bot: `telegram:{token_hash} → tenant_id` (`src/ingestion/main.py:200-260`).
  - Worker heartbeats: `worker:<name>:heartbeat` TTL 45s (`src/data/heartbeat.py`).
  - Queue Bull para n8n (`QUEUE_BULL_REDIS_HOST=redis`).

- [x] **Happy Path RabbitMQ — exchanges + colas pre-declarados con `definitions.json`:**
  **Dado que** RabbitMQ usa la imagen `rabbitmq:3.13-management-alpine` con `RABBITMQ_MANAGEMENT_DEFINITIONS_FILE=/etc/rabbitmq/definitions.json`,
  **Cuando** el broker arranca,
  **Entonces** importa la topología completa sin tener que declararla desde el código:

  **Exchanges declarados** (verificado `infra/rabbitmq/definitions.json:30-47`):
  - `cerebro.ingesta` (direct, durable) — entrada de URLs nuevas.
  - `cerebro.dlx` (direct, durable) — Dead Letter Exchange.
  - `cerebro.procesamiento` (fanout, durable) — eventos del outbox a todos los consumers.

  **Colas declaradas** (verificado `infra/rabbitmq/definitions.json:53-95`):
  - `q.url.ingesta` — TTL 24h (`x-message-ttl: 86400000`), DLX → `dlq.url.fallidas`.
  - `q.url.fallidas` (DLQ) — durable.
  - `q.embeddings` — DLX → `dlq.embeddings.fallidos`.
  - `q.curador.nocturno` — durable.
  - `q.embeddings.fallidos` (DLQ) — durable.
  - `q.notifications` — cola dedicada de notificaciones.

- [x] **Edge Case (DLQ activa):**
  **Dado que** un mensaje falla N reintentos en un worker (scraper/embedder/notifier),
  **Cuando** el worker hace `nack(requeue=False)` o expira el TTL,
  **Entonces** RabbitMQ enruta automáticamente a `cerebro.dlx` por la routing key configurada (`dlq.url.fallidas` o `dlq.embeddings.fallidos`).
  El módulo `src/dlq/dlq_manager.py:1-90` (DLQManager) expone `get_dead_letters()` y `retry_dead_letters()` para reintentos manuales desde el API (`/admin/dlq/*`).

- [x] **Edge Case Redis (fail-open en bloom):**
  **Dado que** Redis devuelve TimeoutError o ConnectionError al ejecutar `BF.ADD`,
  **Cuando** `RedisDeduplicator.is_new_item` captura la excepción,
  **Entonces** activa fail-open (asume "no duplicado"), publica el mensaje a RabbitMQ y emite log WARN (verificado `src/ingestion/deduplicator.py:14-66`). Esto prioriza disponibilidad sobre estricta dedup en caso de fallo del cache.

- [x] **Requisito Técnico:**
  - **Hostname fijo de RabbitMQ** (`cerebro-rabbitmq`) para evitar mismatch de la Erlang cookie tras reinicios.
  - **Erlang cookie** secret: `RABBITMQ_ERLANG_COOKIE: cerebro_erlang_cookie_secret` (en prod debe pasar a `_FILE` — ver F-00.12).
  - **vhost** `cerebro` aislado del default.
  - **Management UI** en `rabbitmq.localhost:15672` vía Traefik.
  - **Métricas exportadas** vía `rabbitmq-exporter` y `redis-exporter` (ver F-06.3).
  - **Rate-limit Redis atómico**: `INCR` + `EXPIRE` si `count == 1` (sin race conditions; ver F-08.4).

**Decisiones tomadas tras el backlog original** (drift documentado):
- Pasar de `redis:alpine` plano a `redis-stack-server` para incluir RedisBloom como módulo nativo (en lugar de tener que compilarlo aparte).
- `definitions.json` declarativo en lugar de declaración dinámica desde código — permite que la topología viva en git y no en el estado interno del broker.
- v1.1 añadió `q.embeddings.fallidos` y `q.notifications` como colas dedicadas — antes vivían en `q.url.fallidas` mezcladas.
- Política `allkeys-lru` en Redis (en lugar de `noeviction`) — el cache puede perder entradas viejas si llega al límite, lo cual está bien para rate-limit y bloom (idempotente).
