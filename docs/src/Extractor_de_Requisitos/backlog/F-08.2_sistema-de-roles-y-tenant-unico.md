**Descripción:**
Como Usuario registrado y autenticado
Quiero **tener mi cuenta vinculada estáticamente a un perfil y Tenant único**
Para que se elimine cualquier posibilidad de que seleccione tenants de forma manual, como ocurre actualmente, garantizando aislamiento estricto y asignación de roles.

> ⚠️ **Estado actual: IMPLEMENTED (con drift)** · El frontend principal Next.js extrae `tenant_id` exclusivamente desde el JWT — el selector de tenant fue eliminado correctamente. **Pero queda un selector legacy en `src/ui/chatbot.py:252` (Streamlit)** que sigue exponiendo `st.selectbox("Tenant", …)`. Si Streamlit es solo herramienta interna admin, debe etiquetarse explícitamente; si no, debe eliminarse.

**Criterios de Aceptación (Checklist):**

- [x] **Happy Path (Next.js):**
  **Dado que** el usuario ha hecho login y recibe cookies `cerebro_session` (httpOnly) + `cerebro_csrf`,
  **Cuando** el frontend Next.js llama a cualquier endpoint protegido,
  **Entonces** `get_current_user` (`src/api/main.py:495-530`) extrae el `tenant_id` desde la claim JWT (`src/api/auth.py:62-66`) — **no desde request, query, ni body** — y lo aplica via `SELECT set_config('app.tenant_id', $1, true)` antes de cada query (RLS-enforced).

- [x] **Edge Case (manipulación de request):**
  **Dado que** un atacante intenta forzar `tenant_id` ajeno en payload, query o header X-Tenant,
  **Cuando** el endpoint recibe la request,
  **Entonces** el valor inyectado es ignorado: solo cuenta la claim JWT firmada con HS256 (rotada por refresh). La RLS de Postgres (`FORCE ROW LEVEL SECURITY` sobre `usuario_recursos`, `sesiones_chat`, `mensajes_chat`, `grafo_relaciones`, `outbox_eventos`) bloquea cualquier acceso cruzado a nivel de fila.

- [ ] **Drift Streamlit legacy (PENDIENTE):**
  **Dado que** `src/ui/chatbot.py:252` aún expone `kb_tenant = st.selectbox("Tenant", tenants_disponibles, …)`,
  **Cuando** algún operador interno o test invoca esa ruta,
  **Entonces** puede consultar cualquier tenant del catálogo (`SELECT DISTINCT tenant_id FROM usuario_recursos`, `:211`).
  > ❌ Decisión pendiente: (a) etiquetar `src/ui/chatbot.py` como `# DEPRECATED — admin-only` y aislar tras VPN/Tailscale, o (b) borrar el módulo legacy. La columna `tenant_id` en la línea `:27` (`tenant_id = st.text_input("Tenant ID", value="default")`) refuerza que es UI multi-tenant sin auth real.

- [x] **Requisito Técnico:**
  - `tenant_id` claim presente en JWT (HS256, expira 30min, refresh 30d, rotation en Redis).
  - `set_config('app.tenant_id', tenant_id, true)` invocado antes de cada query autenticada (`src/api/database.py:122-124, 327-330`).
  - Role `cerebro_service NOLOGIN BYPASSRLS` para workers internos (scraper, embedder, outbox, notifier) que necesitan operar cross-tenant en jobs background.
  - Tabla `recursos` es global (sin RLS) por deduplicación; `usuarios` también (auth en capa API antes de RLS).
