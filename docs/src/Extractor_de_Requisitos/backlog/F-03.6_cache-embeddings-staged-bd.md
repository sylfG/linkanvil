**Descripción:**
Como Operador de la plataforma
Quiero **precalcular y cachear los embeddings de los recursos del seed demo en una tabla `staged_embeddings_cache`**
Para que ninguna sesión demo dispare llamadas reales a LiteLLM al consultar el RAG; el coste marginal de cada sesión demo cae a 0.

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** el operador ejecuta `ops/build_staged_embeddings.py` una vez tras seedear el demo,
  **Cuando** un visitante abre `/demo` y consulta el RAG sobre recursos staged,
  **Entonces** el API resuelve los embeddings desde la tabla cache local y no hace ninguna llamada a LiteLLM (0 calls medidas).

- [ ] **Edge Case:**
  **Dado que** un recurso staged se actualiza o re-seedea,
  **Cuando** el operador relanza `build_staged_embeddings.py`,
  **Entonces** el script es idempotente, regenera solo los recursos cuya firma cambió, y los embeddings antiguos se invalidan.

- [ ] **Requisito Técnico:**
  Migración `0011_staged_embeddings_cache.sql` con la tabla cache. `build_staged_embeddings.py` resuelve embeddings vía LiteLLM una sola vez en build-time. `src/api/main.py` consulta la cache antes de llamar a LiteLLM en consultas RAG sobre recursos staged.
