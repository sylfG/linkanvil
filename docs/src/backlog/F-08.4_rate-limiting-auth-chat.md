**Descripción:**
Como Defensor de la plataforma
Quiero **límites por IP en `/auth/login` y `/auth/register`, y por tenant en `/chat`**
Para frenar brute-force de credenciales y prevenir que un único tenant agote presupuesto LLM/recursos compartidos.

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** una IP ataca `/auth/login` con 6 peticiones en 60 segundos,
  **Cuando** llega la sexta,
  **Entonces** la API responde 429 sin tocar la base de datos.

- [ ] **Edge Case:**
  **Dado que** Redis está caído,
  **Cuando** llega una petición legítima,
  **Entonces** el limiter falla open (no bloquea tráfico real); las métricas registran el evento para alerta.

- [ ] **Requisito Técnico:**
  Limiter atómico Redis (`INCR` + `EXPIRE` solo en la primera incrementación). Topes: `/auth/login` 5/min/IP, `/auth/register` 3/h/IP, `/chat` 30/min/tenant. Se honra `X-Forwarded-For` (Traefik lo setea). `_client_ip()` extrae el primer hop. Implementado como dependencias FastAPI (`rate_limit_login`, `rate_limit_register`, `rate_limit_chat`) que componen con `get_current_user` cuando aplica.
