**Descripción:**
Como Operador
Quiero **un formato de log JSON consistente entre todos los servicios Python**
Para que un backend de logs (Loki/ELK/Datadog/CloudWatch) pueda parsear `trace_id`, `tenant_id`, `service` sin regex y permita correlacionar con las métricas y trazas existentes.

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** un servicio loguea con `logger.info("hello", extra={"trace_id": "abc", "tenant_id": "t1"})`,
  **Cuando** stdout se ingiere en el agente,
  **Entonces** la línea es un JSON válido con `ts`, `level`, `service`, `logger`, `message`, y los campos `trace_id`/`tenant_id` quedan promocionados al top-level.

- [ ] **Edge Case:**
  **Dado que** una excepción se loguea con `logger.exception(...)`,
  **Cuando** se serializa,
  **Entonces** el traceback aparece como string en el campo `exc` y el JSON sigue siendo válido (no se rompe en saltos de línea).

- [ ] **Requisito Técnico:**
  `src/observability/logging.py` expone `configure_json_logging(service)` que reemplaza el handler raíz por un `JsonFormatter`. `LOG_LEVEL` env (default `INFO`). Bibliotecas ruidosas (`uvicorn.access`, `httpcore`, `httpx`) se ponen en `WARNING`. Cableado en `cerebro-api` y `ingestion-api`; los workers (scraper/embedder/outbox) son follow-up trivial.
