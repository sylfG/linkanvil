**Descripción:**
Como Motor de Procesamiento (El Analista) actuando en background,
Quiero detectar **Colisiones Semánticas (cruces automáticos por Similitud de Coseno superior a 0.92) y procesarlas por un "Pipeline Incremental Tipado"**
Para que la base relacional guarde no solo que dos notas están relacionadas, sino **cómo** lo están ("extiende a", "contradice a", "es un tipo de", "vuelve obsoleta a"), permitiendo identificar automáticamente conocimiento desfasado.

**Criterios de Aceptación (Checklist):**

- [x] **Búsqueda Vectorial Pasiva (El Disparo):**
  **Dado que** un nuevo embedding ha sido indexado en `cerebro_recursos`,
  **Cuando** el worker ejecuta `points/search` con `score_threshold: 0.92` y `filter.must=[{key:"tenant_id", match:{value: <tenant>}}]` (`src/data/embedder_worker.py:298-340`),
  **Entonces** el sistema identifica notas históricas del mismo tenant con similitud coseno > 0.92.

- [x] **Clasificación Tipada por IA Compiladora (La Arista):**
  **Dado que** existen documentos semánticamente colisionados,
  **Cuando** `_classify_collision_type` invoca LiteLLM con el prompt "tipifica la relación como UNA ÚNICA PALABRA" (`src/data/embedder_worker.py:246-296`),
  **Entonces** el LLM devuelve uno de los tipos categóricos estrictos `ES_UN`, `CONTRADICE`, `EXTIENDE`, `VUELVE_OBSOLETO` y se inserta una arista en `grafo_relaciones` (`src/data/db.py:520-565`) con `tipo_relacion`, `similitud` y `tenant_id`.

- [x] **Detección Automática de Obsolescencia:**
  **Dado que** el "Pipeline Tipado" devuelve `VUELVE_OBSOLETO` o `CONTRADICE` a favor del documento más reciente,
  **Cuando** se guarda en la DB,
  **Entonces** se crea también la arista inversa (`VUELVE_OBSOLETO` ↔ `OBSOLETO_POR`, `EXTIENDE` ↔ `EXTENDIDO_POR` — `src/data/db.py:540-543`) y el documento antiguo recibe `estado='obsoleto'` (`src/data/db.py:562`) para que el Curador Nocturno (F-05.1) lo trate como stale.

- [x] **Edge Case (Fallo de IA en Tipificación):**
  **Dado que** LiteLLM no devuelve un tipo válido o la llamada falla,
  **Cuando** `_classify_collision_type` no encuentra ninguna de las 4 palabras en la respuesta (`src/data/embedder_worker.py:290-296`),
  **Entonces** etiqueta la relación con el tipo fallback `ASOCIACION_GENERAL` para no perder el cruce ni saturar la DLQ con reintentos infinitos.

- [x] **Requisito Técnico:**
  - Worker en background asíncrono: la clasificación ocurre tras la inyección a Qdrant, dentro del mismo handler del consumer `q.recurso.embedder` (no bloquea ingesta).
  - Threshold de similitud: `0.92` hard-coded en `_compute_semantic_collisions` (configurable a futuro vía env var).
  - Aislamiento per-tenant: el filtro Qdrant garantiza que solo se cruzan recursos del mismo `tenant_id`.
  - Trace ID en logs durante search KNN + LLM classification + insert SQL.
