# [IDENTIDAD] F-08.2 — Sistema de roles y Tenant único por usuario (eliminación de selector de Tenant)

**Épica:** EPIC-08 — Identidad y Control de Acceso

## 🏷️ Categoría

**Categoría:** `Security & Architecture`
**Impacta en:** Aislamiento y Roles de RLS.

## 📦 Dependencias

> Backlogs que deben estar **completados** antes de implementar esta feature.

> **Depende de:** `F-08.1_sistema-de-login`

**Prioridad:** `MUST`

---

**Descripción:**
Como Usuario registrado y autenticado
Quiero **tener mi cuenta vinculada estáticamente a un perfil y Tenant único**
Para que se elimine cualquier posibilidad de que seleccione tenants de forma manual, como ocurre actualmente, garantizando aislamiento estricto y asignación de roles.

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** he logrado hacer Login en el sistema,
  **Cuando** accedo a la interfaz principal (Chatbot e historiales),
  **Entonces** ya estoy anclado en mi entidad o tenant y no veo la opción (selectbox de UI) de cambiar con qué Tenant consultar datos.

- [ ] **Edge Case:**
  **Dado que** intento manipular las requests HTTP / sesiones,
  **Cuando** busco consultar data de otro Tenant,
  **Entonces** RLS y capa de Auth se rechazan porque mi claim solo acepta el mío.

- [ ] **Requisito Técnico:**
  Refactorizar la variable `tenant_id` que provenía de `st.sidebar.selectbox` para extraerla del token de sesión autenticada.
