**Criterios de Aceptación (Checklist):**

- [x] **Happy Path (Fase A · caducidad → cuarentena):**
  **Dado que** existen `recursos` con `estado='activo'`,
  `temporal_class='evento'` y `fecha_caducidad <= NOW()::DATE`,
  **Cuando** el workflow n8n `audit_cron_daily` (cron `0 3 * * *`)
  llama `POST /admin/audit-cron` (`src/api/main.py:1889`) y se ejecuta
  `run_audit_cron()` (`src/data/audit_cron.py:84-135`),
  **Entonces** esos recursos pasan a `estado='cuarentena'` con
  `quarantine_reason='caducidad'` y
  `quarantine_grace_until = NOW() + OBSOLESCENCE_GRACE_DAYS::INTERVAL`
  (default 30 días), emitiendo `recurso.cuarentena` en `outbox_eventos`
  para cada tenant que tenga linkeado el recurso vía `usuario_recursos`.

- [x] **Happy Path (Fase B · gracia agotada → expirado):**
  **Dado que** existen recursos con `estado='cuarentena'` y
  `quarantine_grace_until <= NOW()::DATE`,
  **Cuando** la fase B del cron se ejecuta (`src/data/audit_cron.py:139-160`),
  **Entonces** esos recursos pasan a `estado='expirado'`, emitiendo
  `recurso.expirado` en `outbox_eventos`. Ambas fases son **idempotentes**:
  filtran por estado actual, así que un rerun no produce transiciones
  espurias.

- [x] **Edge Case (sin transiciones · BD al día):**
  **Dado que** no hay recursos a cuarentenar ni a expirar,
  **Cuando** se ejecuta `run_audit_cron`,
  **Entonces** la función devuelve `{trace_id, cuarentenados: 0, expirados: 0}`
  y loguea `Auditoría sin transiciones (BD al día)` con el `trace_id`
  (verificado en `src/data/audit_cron.py:163`).

- [x] **Edge Case (clase temporal incorrecta):**
  **Dado que** un recurso `temporal_class='referencia'` o `'evergreen'`
  tiene `fecha_caducidad` rellena por error,
  **Cuando** el cron itera,
  **Entonces** el filtro `temporal_class = 'evento'` impide la transición —
  se aplica defensa en profundidad para que solo `evento` entre en el flujo
  de caducidad (`src/data/audit_cron.py:124`).

- [x] **Requisito Técnico:**
  - Migración `infra/postgres/migrations/0006_temporal_class_y_strictness.sql`:
    añade `recursos.temporal_class CHECK IN ('evento','referencia','evergreen')`.
  - Migración `infra/postgres/migrations/0007_audit_policy_y_auto_archive.sql`:
    añade `usuarios.audit_policy JSONB NOT NULL` (6 keys per-tenant) que
    permite personalizar el strictness por tenant.
  - Variable `OBSOLESCENCE_GRACE_DAYS` (default `30`) controla la duración
    de la gracia.
  - Cada transición genera un `trace_id` único (UUID4) propagado en los
    eventos `outbox` para correlacionar logs y eventos.
  - El workflow n8n diario está en `infra/n8n/workflows/audit_cron_daily.json`
    (cron expression `0 3 * * *`, header `X-Admin-Token`).
