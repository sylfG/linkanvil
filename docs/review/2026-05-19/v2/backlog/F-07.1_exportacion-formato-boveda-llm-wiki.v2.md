**Descripción:**
Como usuario de la plataforma nube,
Quiero poder desencadenar una exportación de mi cerebro digital, pero no como volcados de markdown o JSON crudos, sino orquestados en el patrón **LLM Wiki**.
Para que al descargar mi archivo y abrirlo localmente en herramientas como Obsidian o Cursor/Claude Code, tenga una bóveda offline-first perfecta, con directorios `raw/`, `wiki/sources`, `wiki/entities`, `wiki/concepts`, y su matriz de configuración `CLAUDE.md`.

> ⚠️ **Estado actual: PARTIAL** · La lógica de generación del ZIP existe completa, pero **no hay endpoint HTTP** que la exponga al usuario. Solo se invoca desde tests (`tests/test_f071_exporter.py`).

**Criterios de Aceptación (Checklist):**

- [x] **Estructuración Física (lógica):**
  **Dado que** se invoca `VaultExporter.generate_vault_zip(tenant_id)` (`src/data/export_manager.py:85`),
  **Cuando** el método compone el ZIP en memoria,
  **Entonces** produce el árbol `raw/<slug>.txt` (textos planos originales), `wiki/sources/<slug>.md`, `wiki/entities/<slug>.md`, `wiki/concepts/<slug>.md` (verificado en `src/data/export_manager.py:235`).

- [x] **Generación de Archivos Maestros:**
  **Dado que** el exportador inicializa la bóveda,
  **Cuando** ejecuta la fase de archivos raíz,
  **Entonces** inyecta dinámicamente:
  - `CLAUDE.md` — reglas base del agente local
  - `index.md` — mapa de navegación con referencias a `wiki/` y `wiki/hot.md`
  - `wiki/log.md` — timeline de eventos histórico (lee `outbox_eventos`)
  (verificado en `src/data/export_manager.py:117-148`).

- [x] **División Ontológica:**
  **Dado que** los recursos del tenant están clasificados (`category` desde `_extract_metadata_with_llm`),
  **Cuando** el exportador itera sobre ellos,
  **Entonces** los rutea a `wiki/sources/` (artículos), `wiki/concepts/` (ideas), `wiki/entities/` (personas/herramientas) según `category` (verificado en `src/data/export_manager.py:235`).

- [ ] **Trigger HTTP del exportador (PENDIENTE):**
  **Dado que** el usuario está autenticado en `/profile`,
  **Cuando** hace clic en "Exportar bóveda",
  **Entonces** el frontend llama a `GET /export/vault.zip` (autenticado + CSRF) que streamea `generate_vault_zip(tenant_id)` con `Content-Disposition: attachment; filename=vault-<tenant>-<ts>.zip`.
  > ❌ Este endpoint no existe en `src/api/main.py` (grep negativo). El método se ejecuta hoy solo desde tests/CLI.

- [x] **Requisito Técnico:**
  - ZIP construido en memoria con `zipfile.ZipFile` (sin escritura intermedia a disco).
  - Aislamiento por tenant: query `SELECT … WHERE ur.tenant_id = $1` antes del bucle de generación.
  - El ZIP incluye `wiki/hot.md` aunque `contexto_comprimido` esté vacío (placeholder `*(Sin contexto disponible)*`).
