**Descripción:**
Como Responsable de seguridad de la plataforma
Quiero **que ningún contenedor se ejecute como root**
Para que un compromiso de un proceso de aplicación no se convierta en un compromiso de uid 0 en el host (defensa en profundidad).

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** la imagen ha sido construida,
  **Cuando** el operador ejecuta `docker exec <contenedor> id`,
  **Entonces** la respuesta nunca es `uid=0(root)`; los servicios Python corren como `cerebro` (uid 1000) y el frontend como `node`.

- [ ] **Edge Case:**
  **Dado que** el `scraper-worker` necesita instalar Chromium vía `patchright`,
  **Cuando** la imagen se construye,
  **Entonces** la cache del navegador queda en `$PLAYWRIGHT_BROWSERS_PATH=/home/cerebro/.cache/ms-playwright` con permisos correctos para el usuario no-root, y el volumen `/data` para el perfil persistente está chowned a `cerebro`.

- [ ] **Requisito Técnico:**
  Cada Dockerfile (`infra/api.Dockerfile`, `infra/ingestion.Dockerfile`, `infra/scraper.Dockerfile`, `infra/frontend.Dockerfile`) declara `USER cerebro` (o `USER node` en el frontend) tras los `COPY --chown=…`. El usuario `cerebro` se crea con uid 1000 explícito para previsibilidad de permisos en volúmenes bind-mounted.
