**Descripción:**
Como Usuario del chat
Quiero **que mis sesiones y mensajes vivan en Postgres con paginación y validaciones de tamaño, y que el frontend exporte e itere sin fugas de memoria**
Para que el historial sobreviva a reinicios del navegador y del backend, no se pueda colapsar el servidor con payloads gigantes y la UI no acumule errores silenciosos al hacer streaming.

**Criterios de Aceptación (Checklist):**

- [x] **Happy Path:**
  **Dado que** el usuario crea una sesión y envía 10 mensajes,
  **Cuando** recarga la página,
  **Entonces** la sesión y sus mensajes se reconstruyen llamando a
  `GET /chats?limit=&offset=` (envelope `{items,total,limit,offset}`) y
  `GET /chats/{id}/messages`, con la sidebar paginada (verificado en
  `src/api/main.py:1977-2030`).

- [x] **Edge Case (payload gigante / paginación abusiva):**
  **Dado que** un cliente envía `POST /chat` con `messages` de 101 elementos
  o un único `content` de más de **32_000** caracteres (≈ 8k tokens),
  **Cuando** Pydantic valida,
  **Entonces** la respuesta es `422 Unprocessable Entity` y el LLM nunca
  recibe la petición (verificado en `src/api/models.py:139-145`:
  `ChatMessage.content: max_length=32_000`,
  `ChatRequest.messages: min_length=1, max_length=100`).
  Equivalente para `GET /resources?limit=999999` → `Query(le=500)` rechaza
  con 422, y `GET /chats?limit=999999` → `Query(le=200)` rechaza con 422
  (verificado en `src/api/main.py:1380,1394,1407,1425,1985`).

- [x] **Requisito Técnico:**
  - Módulos `src/api/{auth,database,models}.py` separan autenticación, acceso
    a BD y schemas Pydantic.
  - Límites Pydantic concretos: `ChatMessage.content: max_length=32_000`,
    `ChatRequest.messages: max_length=100`.
  - Query limits: `Query(limit, le=500)` para colecciones de recursos,
    `Query(limit, le=200)` para chats y notificaciones.
  - Frontend (`src/frontend/app/(app)/chat/page.tsx:199`): usa
    `URL.revokeObjectURL` tras `exportToMarkdown`, registra `console.warn`
    ante chunks SSE inválidos en lugar de tragarlos, y elimina el closure
    stale `assistantSources` leyendo las fuentes desde el estado en el
    `finally` antes de persistir.
  - Cookies httpOnly y CSRF se gestionan en F-08.3.
