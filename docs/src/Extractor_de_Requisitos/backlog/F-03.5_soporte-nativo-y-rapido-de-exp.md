**Descripción:**
Como Usuario propietario de su KB,
Quiero **exportar todo mi vault como ZIP Markdown estructurado (LLM Wiki) sin depender de la plataforma**
Para que pueda llevarme mis datos a cualquier herramienta (Obsidian, Logseq, repositorio Git) sin vendor lock-in.

> ⚠️ Estado actual: **PARTIAL** · Falta: endpoint HTTP autenticado que exponga `VaultExporter` al usuario final. La lógica de generación del ZIP existe y funciona; solo es accesible desde tests/CLI.

**Criterios de Aceptación (Checklist):**

- [x] **Generación del ZIP Markdown LLM Wiki (lógica interna):**
  **Dado que** se invoca `VaultExporter(db_manager).generate_vault_zip(tenant_id)` (`src/data/export_manager.py:85-200`),
  **Cuando** el método ensambla el contenido del tenant,
  **Entonces** produce un `bytes` con un ZIP que contiene:
  - `index.md` (mapa de navegación del vault)
  - `CLAUDE.md` (system prompt para IA externa que use el vault)
  - `wiki/log.md` (timeline derivada de `outbox_eventos`)
  - `wiki/hot.md` (sesiones de chat con `contexto_comprimido` + título + último acceso)
  - `raw/<slug>.txt` (contenido extraído crudo por recurso)
  - `wiki/sources/<slug>.md`, `wiki/entities/<slug>.md`, `wiki/concepts/<slug>.md` (vistas por tipo)

- [x] **Aislamiento por tenant en la exportación:**
  **Dado que** `generate_vault_zip(tenant_id)` recibe el tenant del usuario autenticado,
  **Cuando** consulta Postgres y monta el ZIP,
  **Entonces** todos los recursos, sesiones y eventos provienen del mismo tenant (las queries respetan RLS de F-03.4 o filtran explícitamente por `tenant_id`).

- [ ] **Endpoint HTTP `/export/vault.zip` (PENDIENTE):**
  **Dado que** el usuario hace clic en "Exportar mi vault" en `/profile`,
  **Cuando** el frontend hace `GET /export/vault.zip` con cookie de sesión,
  **Entonces** el backend debe `await VaultExporter(db).generate_vault_zip(user.tenant_id)` y responder con `StreamingResponse(media_type="application/zip", headers={"Content-Disposition": "attachment; filename=vault-<tenant>-<date>.zip"})`.
  > ❌ No implementado: grep negativo de `/export` en `src/api/main.py` confirma que no existe el endpoint. La clase `VaultExporter` solo se invoca desde `tests/test_f071_exporter.py`.

- [x] **Test de cobertura de la lógica:**
  **Dado que** existe `tests/test_f071_exporter.py:49-50`,
  **Cuando** se ejecuta `pytest`,
  **Entonces** verifica que el ZIP generado contiene los archivos esperados de la estructura LLM Wiki.

- [ ] **Requisito Técnico (PENDIENTE):**
  - Endpoint debe ir bajo `dependency=Depends(get_current_user)` para evitar exportar vaults ajenos.
  - Considerar rate-limit (exportación es costosa: I/O DB + serialización).
  - Streaming: si el vault es grande, evitar cargar el ZIP entero en memoria.
