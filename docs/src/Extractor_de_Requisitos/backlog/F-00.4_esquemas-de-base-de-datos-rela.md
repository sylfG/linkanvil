**Criterios de Aceptación (Checklist):**

- [x] **Happy Path — `init.sql` + 11 migraciones idempotentes:**
  **Dado que** `infra/postgres/init.sql` es montado en `/docker-entrypoint-initdb.d/01_init.sql:ro` (verificado `docker-compose.yml:451`),
  **Cuando** un nuevo cluster Postgres arranca por primera vez,
  **Entonces** crea las extensiones (`uuid-ossp`, `pg_trgm`, `unaccent`), los schemas (`cerebro`, `n8n`) y las tablas core del proyecto.
  Después, el servicio `cerebro-migrate` (one-shot, ver F-00.10) aplica las 11 migraciones de `infra/postgres/migrations/000{1..11}_*.sql` en orden numérico, registrando cada una en `cerebro.schema_migrations` (idempotente — se puede re-ejecutar sin errores).

  **Tablas core** (declaradas en `init.sql` y refinadas por migraciones):

  | Tabla | RLS | Propósito |
  |---|---|---|
  | `recursos` | ❌ (global) | URL única deduplicada por `url_hash` (SHA-256). Compartida entre tenants. |
  | `usuario_recursos` | ✅ FORCED | Pivote per-tenant: qué URLs guardó cada usuario. |
  | `outbox_eventos` | ✅ FORCED | Outbox Pattern: eventos pendientes de publicar a RabbitMQ. |
  | `grafo_relaciones` | ✅ FORCED | Grafo semántico (colisionadores `> 0.92`). |
  | `sesiones_chat` | ✅ FORCED | Sesiones de chat con `contexto_comprimido` (campo para F-04.4). |
  | `mensajes_chat` | ✅ FORCED | Mensajes user/assistant + fuentes RAG. |
  | `usuarios` | ❌ (auth API) | Credenciales + `tenant_id` UNIQUE + telegram bot info. |
  | `notificaciones` | ✅ FORCED (mig 0004) | Bandeja de notificaciones por tenant. |
  | `demo_sessions` (mig 0009) | — | Sesiones demo trial. |
  | `demo_session_events` (mig 0010) | — | Telemetría intra-sesión demo. |
  | `staged_embeddings_cache` (mig 0011) | — | Cache de embeddings staged para evitar recálculo. |

  (verificado en `infra/postgres/init.sql:27-244` y migraciones `0001_baseline.sql` … `0011_staged_embeddings_cache.sql`).

- [x] **RLS habilitada y FORZADA con role `cerebro_service` BYPASSRLS:**
  **Dado que** init.sql declara `ENABLE ROW LEVEL SECURITY` + `FORCE ROW LEVEL SECURITY` en las 5 tablas multi-tenant (`usuario_recursos`, `sesiones_chat`, `mensajes_chat`, `grafo_relaciones`, `outbox_eventos`),
  **Cuando** un usuario API hace una query,
  **Entonces** la política `tenant_isolation` filtra por `tenant_id = current_setting('app.tenant_id', true)` (LOCAL setting por transacción).
  El backend invoca `SELECT set_config('app.tenant_id', $1, true)` antes de cada query con el `tenant_id` extraído del JWT (verificado `src/api/database.py:122-124,327-330`).
  **Workers internos** usan el role `cerebro_service NOLOGIN BYPASSRLS` para procesar outbox/embeddings/audit cross-tenant sin set_config (verificado `init.sql:175-178`).

- [x] **Tuning para 2G/2cpu con max_connections=200:**
  **Dado que** Postgres está limitado a 2G de RAM (`deploy.resources.limits`),
  **Cuando** arranca con el `command` overrideado,
  **Entonces** usa: `max_connections=200`, `shared_buffers=512MB`, `effective_cache_size=1536MB`, `work_mem=8MB`, `maintenance_work_mem=128MB` (ver F-00.9 para detalle del tuning; verificado `docker-compose.yml:434-446`).

- [x] **Outbox Pattern garantiza consistencia eventual con RabbitMQ:**
  **Dado que** `outbox_eventos` tiene `procesado BOOLEAN DEFAULT FALSE` + índice parcial sobre `procesado=false`,
  **Cuando** `save_with_outbox` inserta un recurso + evento en la **misma transacción** (verificado `src/data/db.py:214-401`),
  **Entonces** el `outbox-worker` lee `procesado=false` con `FOR UPDATE SKIP LOCKED`, publica a exchange `cerebro.procesamiento`, y marca `procesado=true` (verificado `src/data/outbox_publisher.py:1-200`). Esto desacopla la escritura transaccional de la publicación al bus.

- [x] **Migraciones idempotentes con tracking versionado:**
  - **Baseline** (`0001_baseline.sql`) espeja `init.sql` para clusters ya existentes.
  - **0002** — `recursos_global.sql` (deduplicación cross-tenant).
  - **0003** — `obsolescencia.sql` (campo `quarantine_grace_until`).
  - **0004** — `notifications.sql` (tabla notificaciones).
  - **0005** — `recursos_contenido.sql` (campo `contenido_extraido`).
  - **0006** — `temporal_class_y_strictness.sql` (`temporal_class IN ('evento','referencia','evergreen')`).
  - **0007** — `audit_policy_y_auto_archive.sql` (`audit_policy JSONB` per-tenant).
  - **0008** — `byok_y_demo_flag.sql` (BYOK con virtual keys + flag demo).
  - **0009** — `demo_sessions.sql`.
  - **0010** — `demo_session_events.sql` (telemetría intra-sesión slice 6).
  - **0011** — `staged_embeddings_cache.sql`.

- [x] **Requisito Técnico:**
  - Patrón Dual confirmado: Postgres = textos crudos + metadatos + outbox + RLS. **Cero búsqueda semántica** sobre Postgres (delegado a Qdrant).
  - Trigger `trigger_set_updated_at` automático en `recursos` y `usuarios`.
  - Función SQL `curador_marcar_expirados()` para la primera fase del cron (luego reemplazada por `run_audit_cron` en Python desde F-05.1).
  - Schema `n8n` aislado para que las migraciones del workflow engine no contaminen las tablas propias.

**Decisiones tomadas tras el backlog original** (drift documentado):
- El esquema creció de "esquema inicial" a un esquema versionado con 11 migraciones. La auditoría documental (slice 6) y BYOK añadieron tablas que no estaban previstas en Fase 3.
- `recursos` es **global** (no per-tenant) para permitir deduplicación cross-tenant — un solo scrape sirve a múltiples usuarios. El aislamiento se hace en `usuario_recursos` (pivote con RLS).
- Role `cerebro_service BYPASSRLS` añadido para que los workers (outbox, embedder, scraper, notifier) puedan procesar eventos cross-tenant sin invocar `set_config`.
- Patrón `current_setting('app.tenant_id', true)` (con `true` = missing_ok) — si no hay tenant configurado, la política bloquea (devuelve `NULL ≠ tenant_id`), nunca filtra todo.
