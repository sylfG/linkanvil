**Descripción:**
Como Usuario del chat
Quiero **que mis sesiones y mensajes vivan en Postgres con paginación y validaciones de tamaño, y que el frontend exporte e itere sin fugas de memoria**
Para que el historial sobreviva a reinicios del navegador y del backend, no se pueda colapsar el servidor con payloads gigantes y la UI no acumule errores silenciosos al hacer streaming.

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** el usuario crea una sesión y envía 10 mensajes,
  **Cuando** recarga la página,
  **Entonces** la sesión y sus mensajes se reconstruyen llamando a `GET /chats?limit=&offset=` (envelope `{items,total,limit,offset}`) y `GET /chats/{id}/messages`, con la sidebar paginada.

- [ ] **Edge Case:**
  **Dado que** un cliente envía `POST /chat` con `messages` de 101 elementos o un único `content` de 40k chars,
  **Cuando** Pydantic valida,
  **Entonces** la respuesta es `422 Unprocessable Entity` y el LLM nunca recibe la petición. Lo mismo para `GET /resources?limit=999999`.

- [ ] **Requisito Técnico:**
  Módulos `src/api/{auth,database,models}.py`. El frontend usa `URL.revokeObjectURL` tras `exportToMarkdown`, registra `console.warn` ante chunks SSE inválidos en lugar de tragarlos, y elimina el closure stale `assistantSources` leyendo las fuentes desde el estado en el `finally` antes de persistir. Las cookies httpOnly y CSRF se gestionan en F-08.3.
