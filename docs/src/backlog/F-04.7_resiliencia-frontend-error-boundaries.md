**Descripción:**
Como Usuario de la web
Quiero **que un fallo de render en cualquier componente no me deje la app en blanco**
Para que un crash inesperado (parser de markdown, fetch que rechaza, store en estado inconsistente) muestre una UI de fallback con botón Reintentar y, en caso del panel principal, mantenga la sidebar usable.

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** un componente lanza una excepción durante el render,
  **Cuando** Next.js delega al boundary más cercano,
  **Entonces** se muestra el fallback (mensaje + botón "Reintentar" + enlace "Volver al inicio") y el resto del layout no auth queda visible.

- [ ] **Edge Case:**
  **Dado que** el error ocurre dentro del grupo `(app)`,
  **Cuando** se renderiza el fallback de sección,
  **Entonces** la sidebar lateral sigue navegable y el usuario puede saltar a otra sección sin recargar la página.

- [ ] **Requisito Técnico:**
  Crear `src/frontend/app/error.tsx` (boundary global) y `src/frontend/app/(app)/error.tsx` (boundary del área autenticada). Ambos `"use client"`, reciben `{ error, reset }`, exponen `error.message` solo si `process.env.NODE_ENV !== "production"`.
