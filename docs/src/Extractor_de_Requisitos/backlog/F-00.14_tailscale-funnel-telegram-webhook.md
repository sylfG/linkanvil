**Descripción:**
Como Operador self-hosted
Quiero **exponer el webhook de Telegram con un Tailscale Funnel persistente en lugar de túneles ephemerales tipo ngrok/cloudflared**
Para que la URL pública del webhook no cambie entre reinicios, las credenciales del bot apunten siempre al mismo destino y la superficie expuesta esté controlada por ACLs de Tailscale.

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** el operador reinicia el host de LinkAnvil,
  **Cuando** docker-compose levanta el servicio `tailscale`,
  **Entonces** la URL pública del Funnel permanece estable y Telegram entrega los webhooks al endpoint de ingesta sin reconfigurar el bot.

- [ ] **Edge Case:**
  **Dado que** Tailscale pierde conectividad temporal,
  **Cuando** vuelve a estar disponible,
  **Entonces** el túnel se restablece automáticamente sin requerir intervención manual ni rotación del token del bot.

- [ ] **Requisito Técnico:**
  Servicio Tailscale en `docker-compose.yml` con configuración Funnel en `infra/tailscale/serve.json`. Variables `TS_AUTHKEY` y similares versionadas en `.env.example`. El servicio expone solo el path del webhook, no la red interna completa.
