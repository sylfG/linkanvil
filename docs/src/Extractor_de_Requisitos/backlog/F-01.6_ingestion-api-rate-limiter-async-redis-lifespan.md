**Descripción:**
Como Mantenedor de la Ingestion API
Quiero **eliminar las gomas y parches ad-hoc de la primera versión del servicio (`get`+`incr` no atómico, `redis.Redis` síncrono dentro de handlers async, `@app.on_event` deprecated, regex de URL goloso, CORS inválido) y añadir healthcheck**
Para que el servicio pueda sostener carga concurrente sin saltarse el rate limit, sin bloquear el event loop y sin warnings de FastAPI; y para que `reset.sh` pueda esperarlo de forma fiable.

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** el operador lanza 50 peticiones concurrentes a `/ingest` para el mismo `tenant_id`,
  **Cuando** el limit es 10/min,
  **Entonces** exactamente 10 reciben 200/202 y las restantes 429; nunca pasa más por la condición de carrera.

- [ ] **Edge Case:**
  **Dado que** un usuario envía un mensaje con la URL `Mira: https://example.com/foo.`,
  **Cuando** el regex extrae,
  **Entonces** la URL ingerida es `https://example.com/foo` (sin punto final), no la cadena completa con puntuación.

- [ ] **Requisito Técnico:**
  Migración de `redis.Redis` → `redis.asyncio` en `main.py` y `deduplicator.py`; rate limiter `INCR + EXPIRE` atómico; reemplazar `@app.on_event` por `lifespan`; `extract_urls()` centralizada con strip de `.,;:!?)"'`; `CORSMiddleware(allow_credentials=False)` con `allow_origins=["*"]` (la combinación previa la ignora el navegador); healthcheck `python -c urlopen('/health')`. `INGESTION_RATE_LIMIT_PER_MIN` configurable.
