**Descripción:**
Como Usuario gestionando su KB,
Quiero **un panel administrativo dividido por áreas funcionales (chat, KB, ingest, quarantine, expired, profile, demo)**
Para que pueda navegar entre las secciones de control sin tener que cambiar de aplicación, con un sidebar coherente y notificaciones unificadas.

**Criterios de Aceptación (Checklist):**

- [x] **Happy Path (set de páginas por área):**
  **Dado que** el usuario autenticado navega a `/(app)`,
  **Cuando** la app Next.js renderiza el layout autenticado (`src/frontend/app/(app)/layout.tsx`),
  **Entonces** dispone de las siguientes secciones bajo el group `(app)`:
  - `chat/` — Chatbot RAG (F-04.1)
  - `kb/` — Knowledge Base browser
  - `ingest/` — Subida/captura manual de recursos
  - `quarantine/` — Recursos en cuarentena
  - `expired/` — Recursos caducados
  - `profile/` — Perfil + ajustes + audit
  - `demo/` — Modo demo
  - Cada sección es una página Next.js independiente, no un componente embebido en un dashboard unificado.

- [x] **Notifications Bell global:**
  **Dado que** el usuario está autenticado,
  **Cuando** se renderiza el layout,
  **Entonces** el componente `_NotificationsBell.tsx` (`src/frontend/app/(app)/_NotificationsBell.tsx`) muestra notificaciones unificadas (recursos en cuarentena, caducidades, eventos de audit).

- [x] **Layout autenticado:**
  **Dado que** un usuario sin sesión activa accede a `/(app)/*`,
  **Cuando** el middleware de Next.js comprueba la cookie `cerebro_session`,
  **Entonces** redirige a la página de login antes de servir contenido protegido.

- [x] **Error boundary:**
  **Dado que** una página dentro de `(app)` lanza un error de runtime,
  **Cuando** React lo captura,
  **Entonces** `src/frontend/app/(app)/error.tsx` muestra una pantalla de error elegante en lugar de la pantalla blanca por defecto (F-04.7 cubre el endurecimiento de error boundaries).

- [x] **Requisito Técnico:**
  - Estructura: Next.js App Router con route group `(app)` para layout compartido.
  - Sidebar / navegación: dentro del `layout.tsx`.
  - Páginas separadas por concern, sin "dashboard unificado" con widgets — decisión explícita.
  - Notifications Bell en cabecera, accesible desde cualquier subpágina.

**Decisiones tomadas tras el backlog original** (drift documentado):
- **No es un "Dashboard general con métricas locales"** como decía el backlog original: es un **set de páginas por área funcional** con un sidebar de navegación. La decisión fue priorizar profundidad por área (KB browser completo, quarantine review, expired management) en vez de un home con widgets generalistas.
- Las "métricas" aparecen embebidas en cada página (ej. KB muestra contadores en su propia vista) y en el Notifications Bell, no en una vista de control unificada.
- F-04.7 (no en este lote) endurece los error boundaries del frontend.
