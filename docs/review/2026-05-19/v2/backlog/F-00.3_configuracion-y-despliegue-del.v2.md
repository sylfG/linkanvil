**Criterios de Aceptación (Checklist):**

- [x] **Happy Path — n8n arranca con backend Postgres y queue Redis:**
  **Dado que** el servicio `n8n` declara `image: n8nio/n8n:1.123.37`,
  **Cuando** `docker compose up n8n`,
  **Entonces** arranca con:
  - **Backend Postgres** (no SQLite por defecto): `DB_TYPE=postgresdb`, `DB_POSTGRESDB_HOST=postgres`, `DB_POSTGRESDB_DATABASE=cerebro_brain`, `DB_POSTGRESDB_SCHEMA=n8n` (schema dedicado declarado en `infra/postgres/init.sql:17`).
  - **Queue Redis** para ejecuciones distribuidas: `QUEUE_BULL_REDIS_HOST=redis`, `QUEUE_BULL_REDIS_PORT=6379`.
  - **Health-gated startup**: `depends_on: { postgres: service_healthy, redis: service_healthy }`.
  - **Healthcheck propio**: `wget -qO- http://localhost:5678/healthz` cada 30s.
  (verificado en `docker-compose.yml:547-608`).

- [x] **Bootstrap automático de API key (idempotente):**
  **Dado que** el servicio one-shot `n8n-bootstrap` (`python:3.12-alpine`) arranca tras n8n,
  **Cuando** lee `N8N_API_KEY` del `.env`,
  **Entonces**:
  - Si la key es válida → no hace nada (exit 0).
  - Si la key falta o es inválida → llama al endpoint de n8n con `N8N_USER/N8N_PASSWORD` (basic auth, `admin / cerebro_n8n_pass` por defecto), crea una nueva API key, la persiste en `.env`, y carga todos los workflows JSON de `/app/infra/n8n/workflows/*.json` vía API.
  (verificado en `infra/n8n/bootstrap-apikey.py` + `docker-compose.yml:613-636`).

- [x] **Workflow `audit_cron_daily` precargado:**
  **Dado que** `infra/n8n/workflows/audit_cron_daily.json` existe en el repo,
  **Cuando** `n8n-bootstrap` carga workflows,
  **Entonces** queda activado un cron diario que hace `POST /admin/audit-cron` a `cerebro-api` con el header `Authorization: Bearer ${AUDIT_CRON_TOKEN}` (variable inyectada al contenedor de n8n vía `docker-compose.yml:583`).
  Este workflow implementa el cron de auditoría temporal de F-05.1 (cuarentena/expirado).

- [x] **Persistencia y purga de ejecuciones:**
  - `EXECUTIONS_DATA_SAVE_ON_ERROR=all`: guarda execuciones fallidas para diagnóstico.
  - `EXECUTIONS_DATA_SAVE_ON_SUCCESS=none`: no guarda execuciones exitosas (ahorra espacio).
  - `EXECUTIONS_DATA_PRUNE=true` + `EXECUTIONS_DATA_MAX_AGE=168` (horas, ≈ 7 días): purga automática.
  - Volumen `n8n-data:/home/node/.n8n` persiste config + credenciales encriptadas (verificado `docker-compose.yml:587-589, 895`).

- [x] **Exposición vía Traefik (Host header routing):**
  **Dado que** n8n tiene labels `traefik.enable=true` + `traefik.http.routers.n8n.rule=Host(\`n8n.localhost\`)`,
  **Cuando** el operador navega a `http://n8n.localhost` (con `/etc/hosts` mapping),
  **Entonces** Traefik enruta al puerto interno 5678 con basic auth de n8n delante (verificado `docker-compose.yml:598-601`).

- [x] **Requisito Técnico:**
  - **No SQLite**: backend Postgres obligatorio para concurrencia + tolerancia a fallos.
  - **API key**: `N8N_API_KEY` se inyecta al contenedor; `AUDIT_CRON_TOKEN` separado para autenticar contra `cerebro-api`.
  - **Métricas activas**: `N8N_METRICS=true` expone métricas Prometheus en `/metrics`.
  - **Permisos de fichero**: `N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true` exige `chmod 600` en `~/.n8n/config`.
  - **Cookie laxa en dev**: `N8N_SECURE_COOKIE=false` (en producción debe activarse vía `docker-compose.prod.yml` — ver F-00.12).
