**Descripción:**
Como Operador de la plataforma
Quiero **un script `scripts/backup.sh` que produzca dumps gzipped de Postgres y snapshots de cada colección de Qdrant**
Para que un fallo de disco o una corrupción no signifique perder la KB del usuario (los únicos datos no recreables del sistema).

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** la cron del host invoca `bash scripts/backup.sh` a las 03:00,
  **Cuando** el script termina,
  **Entonces** existen `backups/postgres_<db>_<TIMESTAMP>.sql.gz` y `backups/qdrant_<TIMESTAMP>.tar.gz`, ambos con tamaño > 0 y rsyncable a una ubicación off-host.

- [ ] **Edge Case:**
  **Dado que** un snapshot deja residuos en el volumen de Qdrant,
  **Cuando** termina la copia,
  **Entonces** el script invoca `DELETE /collections/<col>/snapshots/<snap>` para que el espacio dentro del contenedor no crezca con cada ejecución.

- [ ] **Requisito Técnico:**
  `BACKUP_DIR` y `BACKUP_RETENTION_DAYS` (default 7) son configurables. La poda usa `find -mtime`. El script lee `POSTGRES_PASSWORD` desde `.env` y se ejecuta sin prompts (cron-friendly), saliendo con código no-cero ante cualquier fallo para que la cron sea diagnosticable.
