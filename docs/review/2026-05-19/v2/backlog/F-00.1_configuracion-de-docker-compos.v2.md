- [x] **Aislamiento de red — `cerebro-net` como bus único:**
  **Dado que** todos los servicios declaran `networks: [cerebro-net]`,
  **Cuando** un servicio invoca otro por nombre DNS (`redis`, `postgres`, `rabbitmq`, `qdrant`, `litellm`),
  **Entonces** la resolución sucede dentro de la red `cerebro-net` (driver `bridge`, `name: cerebro-net`) y no expone esos puertos al host salvo los listados arriba (verificado en `docker-compose.yml:905-910` y bloques `networks:` de cada servicio).

- [x] **Healthchecks y `depends_on` con `condition: service_healthy`:**
  **Dado que** los servicios stateful definen `healthcheck:` (postgres `pg_isready`, redis `redis-cli ping`, qdrant TCP probe a 6333, rabbitmq `rabbitmq-diagnostics ping`, n8n `wget /healthz`),
  **Cuando** los workers o el API arrancan,
  **Entonces** `depends_on:` espera el estado `service_healthy`/`service_completed_successfully` antes de iniciarse (verificado en `docker-compose.yml:60-65,100-105,138-143,170-175,178-198,455-460` para healthchecks y `condition` clauses).

- [x] **Requisito Técnico — volúmenes persistentes y trazabilidad:**
  - Volúmenes nombrados para datos no recreables: `postgres-data`, `qdrant-data`, `rabbitmq-data`, `redis-data`, `n8n-data`, `grafana-data`, `prometheus-data`, `jaeger-data`, `playwright-profile`, `tailscale-state` (verificado `docker-compose.yml:891-901`).
  - Cada servicio Python invoca `configure_telemetry()` desde `src/telemetry.py` para emitir trazas OTLP → otel-collector → jaeger/prometheus.
  - **Drift respecto al backlog v1.1**: `start_core.sh` arrancaba `cerebro-chat` (servicio inexistente) y `reset.sh` referenciaba una versión OTel distinta a la del compose. Ambos corregidos en commit `54805a4`.
