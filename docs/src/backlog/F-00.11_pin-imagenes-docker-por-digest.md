**Descripción:**
Como Operador de la plataforma
Quiero **que toda imagen externa esté pinneada por digest (`tag@sha256:…`)**
Para que `docker compose pull` sirva siempre los mismos bytes y no rote silenciosamente entre versiones diferentes (riesgo característico de `:latest` y `:main-latest`).

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** un nodo nuevo arranca el stack,
  **Cuando** ejecuta `docker compose pull`,
  **Entonces** el daemon resuelve cada imagen por digest exacto y `docker inspect` reporta el mismo `RepoDigests` que el head node de referencia.

- [ ] **Edge Case:**
  **Dado que** el upstream borra el tag (p. ej. invalidan `main-latest`),
  **Cuando** se intenta pullear,
  **Entonces** el digest sigue siendo válido en el registry y la imagen continúa siendo recuperable hasta que se actualice manualmente el pin.

- [ ] **Requisito Técnico:**
  Cuatro imágenes pasaron de tag rotatorio a `tag@sha256:<digest>`: `redis/redis-stack-server`, `jaegertracing/all-in-one`, `ghcr.io/berriai/litellm`, `kbudde/rabbitmq-exporter`. El comentario al lado del primer pin documenta el flujo de bump (`docker pull` → `docker inspect ... RepoDigests` → reemplazar en `docker-compose.yml`).
