**Descripción:**
Como usuario conversacional,
Quiero poder desencadenar una exportación de mi cerebro digital, pero quiero que el contexto de las charlas o los recuerdos de mis resúmenes asíncronos conversacionales viajen también.
Para que agentes de LLM locales (por terminal de PC, como Claude Code) puedan retomar inmediatamente un Chat "Sincronizado" utilizando `hot.md` (patrón *Hot Cache* de la Bóveda Claude-Obsidian).

> ⚠️ **Estado actual: PARTIAL** · La generación de `wiki/hot.md` existe en `VaultExporter`, pero la fuente de datos (`sesiones_chat.contexto_comprimido`) está **siempre vacía** porque F-04.4 (compactación de sliding window) está PARTIAL: la columna existe pero ningún job la rellena. El `hot.md` resultante solo contiene títulos+timestamps con placeholder "*(Sin contexto disponible)*".

**Criterios de Aceptación (Checklist):**

- [x] **Sincronización de Sliding Window a Markdown (estructura):**
  **Dado que** existen sesiones en `sesiones_chat` para el tenant,
  **Cuando** `VaultExporter.generate_vault_zip` ejecuta la fase hot.md,
  **Entonces** genera `wiki/hot.md` iterando sesiones (`src/data/export_manager.py:137-148`):
  ```
  ## <título sesión>
  **Último acceso:** <ultimo_acceso>

  ### Contexto Comprimido (Sliding Window)
  <contexto_comprimido | "*(Sin contexto disponible)*">
  ```
  (verificado en `src/data/export_manager.py:60` query + `:143-147` render).

- [ ] **Continuidad Cognitiva Local (PENDIENTE — bloqueado por F-04.4):**
  **Dado que** el usuario abre `wiki/hot.md` con un agente LLM local,
  **Cuando** consulta "Resume en qué nos quedamos la última vez",
  **Entonces** el agente lee resúmenes reales producidos por la compactación sliding window.
  > ❌ Hoy `contexto_comprimido` está siempre vacío. La columna existe (`infra/postgres/migrations/0001_baseline.sql:106-116`) y los helpers `update_session_context`/`get_session_context` (`src/data/db.py:103-139`) están listos, pero **no hay job de compactación activo** — el chat envía los 100 mensajes (cap Pydantic) sin sliding window real.

- [x] **Logs Generales:**
  **Dado que** `outbox_eventos` registra todos los eventos del sistema (ingesta, colisiones, expiraciones),
  **Cuando** el exportador genera `wiki/log.md`,
  **Entonces** itera el outbox por tenant y produce un timeline:
  ```
  1. **[<fecha>]** `<tipo_evento>` sobre `<agregado>` (<id>) - *<estado>*
  ```
  (verificado en `src/data/export_manager.py:127-135`).

- [ ] **Acceso vía HTTP (PENDIENTE — heredado de F-07.1):**
  Sin endpoint `/export/vault.zip`, el `hot.md` y `log.md` solo se generan en tests.

- [x] **Requisito Técnico:**
  - Aislamiento por `tenant_id` en la query de sesiones (RLS via `set_config('app.tenant_id')`).
  - Placeholder defensivo cuando `contexto_comprimido IS NULL` (no rompe el ZIP).
  - `log.md` se ordena cronológicamente (DESC por `creado_en`).
