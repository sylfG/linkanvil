**Descripción:**
Como Usuario consultando el chatbot RAG
Quiero **que el sistema chunkee los recursos en piezas estables (≈1200 chars con split en `\n+`) y los almacene en la tabla `cerebro_chunks`, alimentando un contexto de hasta 32k tokens al LLM**
Para que las respuestas tengan recall y precisión sin desbordar la ventana ni perder contexto largo en documentos web extensos.

**Criterios de Aceptación (Checklist):**

- [ ] **Happy Path:**
  **Dado que** se ingesta un artículo web largo (>10 KB de texto),
  **Cuando** el embedder lo procesa,
  **Entonces** se generan N chunks de ≈1200 chars en `cerebro_chunks`, se indexan vectorialmente, y el RAG selecciona los más relevantes para construir un prompt de hasta 32k tokens enriquecido con resumen y prompt estricto.

- [ ] **Edge Case:**
  **Dado que** dos chunks producen vectores casi idénticos por contenido repetido,
  **Cuando** el colisionador semántico calcula similitud,
  **Entonces** clamp `min(value, 1.0)` evita la violación de la constraint `CHECK` en `grafo_relaciones`.

- [ ] **Requisito Técnico:**
  Migración `0005_recursos_contenido.sql` añade tabla `cerebro_chunks`. `embedder_worker.py` ejecuta el chunking (1200 chars + split `\n+`). API enriquece el contexto con resumen de Postgres y aplica prompt estricto. Inicialización idempotente en `infra/qdrant/init_qdrant.sh`.
